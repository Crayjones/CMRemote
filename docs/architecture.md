# Architecture and lifetime rules

## Boundaries

```
Qt Widgets main thread
  MainWindow → DocumentContext → rust::Box<rm::Core> (password-free cxx)
  tree / Config / SessionPane / DesktopView / TerminalView + libvterm
       ↑ owned GUI delivery                 ↓ bounded commands/cancel
  C++ RdpWorker / FreeRDP        SshWorker facade → QThread / russh / Tokio
  serialized DocumentService    independent trust / appearance services
```

SSH authentication has a separate session-only cxx handoff; document masters and document crypto keys never cross it. Rust mock workers remain explicit test paths.

`app/ui/test.ui` is the approved production Designer shell, shared with the standalone preview. Production clears Designer sample profiles, session pages and notifications before loading Rust data. `MainWindow.cpp`, `MainWindowMenus.cpp` and `ProfileEditor.cpp` bind production behavior; C++ creates dynamic panels, tabs and session views. Other forms define static dialogs. No QML, Rust QWidget bindings, external client processes or window reparenting are used.

The standalone preview links only Qt, keeps samples in memory and never accesses production profiles, credentials or networking. Form/resource changes require both production and preview regressions. Both builds use the curated `vendor/mremoteng-assets/` subset; no full upstream checkout is needed. Unresolved per-image rights block redistribution. See [dependencies](dependencies.md#curated-original-ui-assets--redistribution-blocked).

Rust Core owns validated password-free committed metadata, inheritance, reserved candidates and session records. C++ owns Qt objects, XML/encryption/persistence, FreeRDP and GUI-owned libvterm state. The standalone russh backend owns its transient authentication/socket/runtime without borrowing Core or widgets. FreeRDP callbacks/framebuffers become Qt-owned images; SSH output becomes an owned bounded GUI byte drain. Core has no production path-based persistence API.

## cxx bridge

`core/src/bridge.rs` defines the bridge. Each GUI-owned `DocumentContext` owns a `rust::Box<rm::Core>` from `detached_core`; MainWindow also owns a separate Core for temporary sessions. Methods run only on the GUI thread. No worker borrows Core, and no Rust borrow survives a call. Core rejects saved-profile operations until a validated document has been loaded; session bookkeeping remains available.

The ordinary bridge exchanges owned password-free JSON, `PreparedProfile` tokens/IDs/candidates, `RdpTarget`/`SshTarget`, `SessionInfo` and `SessionEvent`. `load_document` adopts validated input; `prepare_profile` reserves at most one candidate without changing memory or disk. The GUI sends owned candidate JSON to the storage worker, then calls `finish_profile(token, committed)` after replacement. Foreign/stale tokens fail. Snapshot `effective` fields are display-only and removed from mutations. Draft previews use the same resolver as committed profiles. Errors omit input JSON.

Only the separate `rm::ssh` bridge consumes opaque session-only password/passphrase authentication. It is not a Core/profile/session field or serializable auth record. Key-file reading/decoding is off-GUI and bounded; document master/crypto keys remain C++-owned. See [SSH API and limits](ssh-api.md).

cxx checks the C++/Rust boundary during generation and compilation. CMake builds the locked Rust static library, includes Cargo's generated bridge headers, then links the frontend. MainWindow explicitly closes its tabs before Core is destroyed. Qt child ownership handles static widgets; SessionPane explicitly owns/stops its network worker.

## Profiles and persistence

Production backing files are mRemoteNG-compatible connection XML, detected by contents regardless of suffix. `ConnectionXml` owns a passive XML tree in the storage worker and projects password-free schema-1/2 JSON into Rust. Schema 2 includes bounded Description/Domain, typed RDP options and nonsecret SSH auth/key-path fields. SSH Username is literal, Domain is passive, and irrelevant RDP settings cannot block SSH; common launch-critical/unknown settings still do. `None` means inheritance; explicit empty strings and false differ. Native defaults and inheritance flags are mapped explicitly; app-only host/fixed-resolution preferences use ignored extensions plus compatible effective/fallback values. Unknown fields, namespaces and opaque nodes survive ordinary edits. Unsupported launch-critical settings disable Connect instead of silently changing the target.

Each loaded file has its own runtime `DocumentId`, context/Core, revision, candidate reservation, selection/expansion and master state. Portable file/profile UUIDs are not runtime identities. `ProfileReference = (DocumentId, profile UUID)` and separate `DocumentRootReference` route tree, Config, sessions and completions. Copies with identical UUIDs do not alias. Same physical-file aliases are rejected/focused, not opened as independent writers. New/Open/Save/Save as/Close act on the owning file; Save as rebinds only after replacement and leaves source bytes unchanged. Close blocks while any associated saved tab remains.

Config is a compact two-column delegate grid, without permanent editors or Source text. Local values are bold; inherited values are normal. Properties/Inheritance and Categorized/Alphabetical are exclusive pairs. Inheritance controls and the property context command remove local overrides. `ProfileEditor` holds committed input plus an unsaved candidate. Enter/focus loss emits a dedicated user-commit event; Escape and unchanged commits do not write. Load/render/preview signals never trigger saves. Persistence is scheduled after delegate commit/close unwinds. Invalid candidates remain editable; cycles, invalid accounts/settings, missing parents, duplicate IDs, bounds violations and unknown versions/fields are rejected.

Selection, context commands, mode changes, drag, Connect/Reconnect and close/native Quit share a settle-save guard. Writes serialize, with mutations briefly gated while a candidate is pending. Ordinary saves need no dialog. Failure keeps the unsaved value and old file/model; Retry / Revert / Cancel controls recovery, default Cancel. Canceled protected re-unlock blocks the continuation. Successful reconciliation preserves property selection, expansion, scroll, mode, sort/filter and UUID selection. Settled refreshes adopt existing rows only for the same runtime DocumentId, profile UUID and root/profile kind; identity/shape changes reload. Dirty drafts and active editors survive foreign-file refreshes. Declarative field protocol metadata filters by resolved effective Protocol in Properties/Inheritance, including folders, without removing hidden overrides or rebuilding rows. Post-replacement warnings gate continuations until acknowledgement.

`AtomicFile` serves document, SSH trust and terminal-preference stores: safe canonical paths, sidecar lock, revision checks, owner-only Unix permissions, same-directory `QSaveFile` with direct-write fallback disabled, then Unix parent sync. **Replacement is the commit boundary.** Before it, abort the candidate; afterward, finalize it even if Cancel/Lock/close invalidates the navigation intent. Terminal outcomes survive cancellation until reconciliation and warning acknowledgement. Plain/protected documents reject external revisions. This is conflict rejection, not merge support or protection against every malicious filesystem race; use one writer per physical file.

`DocumentService`'s single serialized worker owns XML stores and reusable secrets. Each document has an independent generation, idle deadline, reservation and terminal outcome. Production add/edit/delete/move/password/protection/Save as uses prepare → owned worker persistence → finalize. No worker borrows Core, and protected writes never stage plaintext. Loading/locked/error states gate only the owning file. Full-encrypted startup exposes its typed root until authentication and validated load; password-only mode can display metadata while credentials/writes remain locked. Corrupt/unsupported inputs never become an empty-document fallback; an absent default path creates only a deferred-write new document. Root protection/master changes require explicit consent and re-encrypt all known values in one XML replacement. Committed outcomes remain reconcilable after cancellation/Lock; stale lookup results do not.

The current application is XML-only; retired `LegacyConnection`, vault services and JSON/RMCONS conversion routes are absent. Historical validation below its dated headings describes older revisions, not available current APIs. Existing inactive XML archives remain passive encrypted data and do not authorize a login. See [password ownership and backup limits](password-vault.md).

`ConnectionTree` uses a private process-local MIME subtype containing an exact tree-owner pointer, source document identity, live generation and immutable UUID. Destination must belong to the same document, including root drops; cross-file/window/external drops reject. Serialized bytes alone cannot authorize a drop. Feedback rejects foreign/invalid/cyclic/current-parent drops; final preparation revalidates against committed data. `startDrag` and `dropEvent` never use Qt's default internal move: tree reparenting waits for successful persistence. Root is a document selection, not a profile UUID. Moves retain UUIDs/local fields/subtrees and recompute inheritance. Preview drag is disabled.

Saved sessions retain a runtime document/profile association. Temporary sessions never enter the document. File → Save as connection creates a complete profile with the captured protocol/account/options and a new UUID, without authentication secrets or retargeting the page. The Quick Connect prompt's Save to Connections runs the same flow and additionally sets the typed RDP/SSH password with consent bound to the new profile's endpoint/account. Running targets remain immutable after edits or moves; saved Reconnect resolves the latest committed settings. Nonempty RDP Domain requires an unqualified Username; qualified names/UPNs remain valid with empty Domain. SSH Username is literal and its preserved Domain inactive. Effective inherited account combinations are validated, not silently rewritten.

## Sessions and UI events

Core assigns session UUIDs independently of profile UUIDs. Production saved Connect and Quick Connect share `requestSession` / `attachSession`, selecting the real RDP or SSH adapter. Quick Connect defaults to RDP and supplies SSH's port 22 when no port is given. Registration follows accepted credentials. Saved-page reuse scans every panel by runtime document/profile; temporary reuse includes protocol, normalized endpoint, accepted account and captured options. Saved/temporary pages never alias; disconnected registrations remain in reuse and file-close/delete guards.

Disconnect marks a page inactive and stops its backend while retaining its page/registration. Close additionally removes the registration/page. Reconnect resolves a matching Password in the owning file or prompts; private-key mode always bypasses saved Password lookup. Cancel retains the disconnected page. Acceptance replaces it at its current position with a new session UUID/worker and preserves its caption. Saved Reconnect uses committed settings; temporary Reconnect retains its captured target/account. SSH retirement/reconnect is asynchronous with no GUI join; RDP retains its existing join behavior.

Panel bookkeeping iterates actual `groupTabs` pages and their inner tab widgets. Ownership is resolved by page membership, not QObject parent, caption or a cached index. Rename/reorder/move never changes identity or the running target. Context actions capture stable profile IDs, `QPointer` pages/panels or persistent model indexes and revalidate at execution. The UI blocks subtree deletion while any associated page remains across all panels, including disconnected pages, and checks again when deletion confirmation executes. General is protected by metadata, not its caption.

Panel/application closure cancels pending credentials/trust/lookups, invalidates callbacks and stops owned sessions before final destruction. SSH facades retire outside SessionPane: native threads join off-GUI, and shell closure completes asynchronously after their exit. Session callbacks check current worker/page/generation and active state. No application context-menu filter intercepts RDP's remote right-click. SSH's local terminal menu offers direct-user Copy/Paste and appearance settings. Unsupported protocols, generic import/export and external-execution commands remain disabled; XML Open/Save as use the file controllers.

Rust mock sessions have bounded command/event queues and a separate stop channel. Event publication does not wait for the GUI. Dropping a mock session stops and joins its thread. A GUI timer drains owned events across every panel and posts guarded, queued Qt invocations. Mock desktop and terminal views report input/resize but do not implement real protocols or terminal emulation. They are explicit test paths, never a production Connect fallback.

The RDP adapter is a QThread subclass. Its QObject remains GUI-affine; `run()` executes on the worker. GUI calls only methods that protect command/lifetime state with mutexes. Keyboard/mouse commands are bounded; overflow stops the session rather than silently losing a key release. Resize/clipboard commands coalesce to the latest value. The graphics policy disables asynchronous channels and enables synchronous dynamic-channel dispatch, keeping GDI/GFX production on the worker. Shared display-channel interfaces/capabilities use a separate mutex. Clipboard protocol state is worker-owned; GUI authorization and local text enter through the command queue, while incoming owned deliveries use a bounded mutex-protected mailbox.

RDP worker-to-widget connections are explicitly queued. Lambdas check active state or use QPointer before dereferencing objects. Closing a tab makes it inactive before cancellation and prevents late events from touching its view. Certificate callbacks decide immediately, with no worker certificate signal, dialog or wait. Asynchronous credential dialogs and the worker's credential wait remain; stop wakes that wait and dismisses those dialogs. Input focus loss releases held keys/buttons; drag release outside the displayed image is clamped rather than lost. Automatic desktop resize is debounced and gated on the captured option, backend readiness and an initial frame, rather than sending DISP during activation. Fixed-size desktops are aspect-ratio scaled with remote pointer mapping. The worker checks each FreeRDP setter for account/domain and typed settings; initial dimensions/color negotiation are separately observed by live tests. Server preference enforcement is not assumed. Connected panes have no status-row space; status returns on disconnect.

The shared menu bar is File / View / Tools / Help. View follows the approved ordering, with disabled Screenshots/external/Multi SSH execution. Jump To rebuilds for existing docks/panels/pages using guarded pointers and current membership, never captions or cached indices; it focuses without registration or persistence. Production Jump commands settle active edits. macOS menus are native from construction. Designer assigns Preferences/Quit/About roles before actions enter menus. Tests inspect and dispatch this process's actual AppKit menu; `isNativeMenuBar()` alone is insufficient. Other platforms use in-window menus. Startup and smoke launch never initiate networking. Notifications use generic state text; clipboard writes from notification/hostname Copy occur only on explicit commands. RDP clipboard sharing is separately opt-in, text-only and focus-gated; SSH clipboard access requires direct-user Copy/Paste.

## SSH transport, terminal and appearance

`SshWorker` is a GUI-affine facade over a standalone QThread/current-thread Tokio backend, with owned immutable target/authentication. Context-bound asynchronous Qt DNS precedes socket work; cancellation invalidates DNS delivery without promising OS resolver interruption. russh checks the host key before authentication and reports Connected only after authentication plus successful PTY/shell replies. Ordinary stages have 30-second guards, host approval 120 seconds, and each resolved-address connect attempt five seconds. Fixed public failures omit raw library/server diagnostics. Unsolicited forwarding/X11/agent channels are denied.

The transport bounds input to 256 KiB, output to 1 MiB/64 packets, packets to 32 KiB and GUI drains to 128 KiB. Accepted bytes remain ordered under backpressure and normal EOF. A separate cancellation signal cannot be blocked by data capacity. A coalesced queued wake reaches the facade on the GUI; output is parsed directly only by the current active pane/generation. libvterm never runs on the transport thread.

`TerminalScreen` owns bounded GUI-only UTF-8 cells, alternate screen and scrollback (10000 lines/16 MiB). `TerminalView` renders cells/cursor/selection and encodes keyboard/IME/paste through libvterm. Logical font metrics drive rows/columns and the existing PTY resize route. Direct-user Copy/Paste uses the injected clipboard endpoint; inactive paste is disabled and disconnected text stays copyable. OSC selection callbacks are absent; remote titles/OSC/DCS/hyperlinks cannot read the clipboard or launch local resources. This is separate from RDP CLIPRDR consent/routing.

Independent `SshHostKeyService` and `TerminalAppearanceService` workers own bounded, conflict-checked `AtomicFile` persistence under app-data, not beside each opened XML. Trust save must finish and its committed warning be acknowledged before authentication; connect-once never writes. Appearance publishes only after successful persistence. The dialog previews synthetic text in a real TerminalView with a no-access clipboard endpoint. Apply/OK commit, Cancel keeps the last applied state, and Reset changes draft only. Classic/default/ANSI 0–15 updates preserve text/history/alternate state/cursor/selection; explicit RGB and extended indices remain unchanged. Font6–48pt updates live logical cells without an Apply-induced reconnect/retarget; RDP is unaffected. See [SSH API](ssh-api.md) for key/cache bounds and exact choices.

## Cursor and clipboard ownership

FreeRDP's pointer cache stays intact. The client prototype owns validated alpha cursor images independently of borrowed masks; one latest-value mailbox publishes to the current SessionPane connection generation. Native cursor construction happens on the GUI thread. DesktopView follows the supplied shape/hotspot over the presented desktop and during drags, restores the normal pointer outside it, and resets on failure/disconnect/reconnect. Cursor geometry follows presentation scale and DPR, without global pointer warping.

MainWindow supplies an injectable `ClipboardEndpoint`. RDP obtains QClipboard lazily only after explicit sharing consent; SSH uses it only for direct-user Copy/Paste, never remote-output/focus synchronization. `SessionClipboard` routes existing/new host text to the focused visible authorized desktop. The tab action supports saved-password sessions that skipped the credentials prompt. Permissions remain session-only and reset on reconnect; no XML/Rust/preference permission state is added.

`ClipboardProtocol` keeps channel sends and UTF-16LE snapshots on the worker. Text-only CLIPRDR may negotiate while inert: disabled sessions never access the host clipboard, offer/request text or successfully answer data requests. Requests are serialized and deliveries carry permission, routing and observed-host revisions. A focused-origin copy may complete after host-application focus, but cannot overwrite changed host text or reach a replacement session. Equality/source tracking suppresses delayed echo without blocking global clipboard signals. Disabling releases cached session text/provenance and pending deliveries, without changing the user's clipboard or recalling remote data already sent. Tests inject an in-memory endpoint before any possible host access, including live shell tests.

Quick Connect shares bounded compact sizing with the standalone preview. Production has an RDP/SSH protocol selector beside the address history. Selection does not register a session. Notifications starts hidden, including after Reset Layout. Dock/toolbar visibility synchronization uses explicit hidden state with blocked action signals so host minimization is not recorded as a user hide.

`ApplicationPreferences` receives an explicit application-data path from `main`, never derives it from a connection file and never uses global QSettings. A serialized worker inspects bounded versioned JSON and atomically replaces it using `AtomicFile`. Options edits a dialog-local nonsecret draft; successful replacement applies supported values, including when directory sync returns a durability warning. Cancel does nothing. Only Config grouping/help, Quick Connect visibility and toolbar locking persist; Notifications visibility and fullscreen suppression do not.

Windows are browser-style. Every window has a panel bar whose panels hold session tabs: the main window's `groupTabs`, plus one `PanelWindow` per dragged-out window. `MainWindow::groupBars()` lists them; `sessionPanels()` spans all of them, so session ownership, credential-attempt validation, reconnect replacement and close paths are unchanged. `tabDragEvent` filters every tab bar: inside a strip QTabBar reorders; moving onto another strip, or vertically out of the strip by 20 px, ends QTabBar's own move with a synthetic release and starts a drag. Over no strip, the item tears into a new `PanelWindow` (a session gets a new panel) that follows the cursor; a window holding only the dragged item moves as a whole. Release over a strip moves the item there and removes panels/windows left empty. `currentSessions()` targets the window whose tabs were pressed or activated last. Each window has its own `SessionFullscreenController`, which only changes that window's presentation. QRhiWidget keeps the GPU context of the last window it rendered in until it renders again and dereferences it on destruction, so a retired window stays hidden until every session alive at retirement is destroyed.

## Frame ownership and teardown

FreeRDP software GDI applies every incremental update to its private framebuffer. BeginPaint resets both the invalid-region marker and region count. Legacy EndPaint captures owned RGB32 damage patches; it represents an update block, not necessarily a complete visual frame. GFX EndPaint calls accumulate damage from every mapped surface, and one batch is captured after successful EndFrame or an inter-frame flush. A failed flush discards its pending publication. The GUI never reads mutable GDI memory.

`DesktopUpdateAccumulator` captures complete 64×64 dirty tiles under the worker's frame mutex. Repeated damage replaces a tile's pixels; disjoint tiles survive coalescing. Initialization and geometry changes require a full snapshot. More than 512 pending tiles, excessively fragmented damage or approximately half-desktop tile coverage also select full recovery. A queued full snapshot receives subsequent sparse changes by row copies, without another whole-desktop copy. Bounds remain 8192 per axis and 16 Mi pixels. Batches carry geometry/revision stamps, the oldest pending timestamp and replacement counts. Stale revisions and incompatible geometry are rejected.

`RdpConfig` captures an internal session graphics policy, default GFX with explicit legacy comparison mode. Only 32-bit profiles advertise GFX/RFX; AVC flags additionally require an actual linked software decoder context. This does not establish which codec the server uses. Typed telemetry records incoming codec IDs separately. No security downgrade or retry fallback is added.

`RdpGfxPipeline` calls pinned GDI initialization directly using the explicit `RdpGraphicsContext` prefix, never a common-handler `rdpClientContext` cast. `gfx->custom` remains GDI-owned while active. Callback wrappers retain underlying GDI processing. Partial initialization frees assigned codecs/restores callbacks without touching the not-yet-initialized mutex. Successful teardown deletes remaining tracked surfaces, reports cleanup failures, uninitializes once and restores prior callback ownership. Saved wrappers reject restored interfaces before reading `custom`. Channel OnClose runs with GDI callbacks valid; disconnect notification closes the helper before GDI/context storage is freed.

Desktop dimensions are bounded to 8192 per axis and 16 Mi pixels. Legacy resize resets the planar decoder allocation through its public API before replacing the framebuffer. The old-primary EndPaint keeps its old geometry stamp; the geometry epoch advances only after successful replacement. Same-size resize does not advance it. Failure closes the session rather than accepting incompatible storage.

At most one frame notification is posted until the GUI drains the owned damage mailbox. Production SessionPane calls `takeUpdate()` and accepts batches only from its current, active connection generation and running worker. `takeFrame()` remains a compatibility adapter for older tests/callers; it is not the production handoff. Shutdown and supersession invalidate queued callbacks before joining; a new connection clears the old image. Disconnect may retain the last accepted image in the old tab, but reconnect does not restore it.

DesktopView applies validated batches to its authoritative CPU QImage and retains GPU damage until upload preparation succeeds. It does not retain an unnecessary shared submitted CPU image; external `frame()` snapshots still receive QImage copy-on-write protection. Sparse QRhi uploads own compact image patches with explicit destination offsets. Full recovery owns copied BGRA bytes, including padded row strides. GPU work never refers to mutable GDI or borrows the authoritative CPU desktop. Resource recreation always reuploads the complete retained desktop.

QRhiWidget's initialization and rendering callbacks run on the GUI thread, not a separate render thread. Frame/resize events request updates; there is no continuous repaint loop or presentation timer. The GPU cache is committed only when shaders, texture, sampler, bindings, vertex buffer and a target-compatible graphics pipeline are ready. Failure retains the CPU frame and pending upload, displays a renderer-unavailable label, and retries on the next update. Letterboxing/input use logical widget pixels while the render viewport uses physical target pixels. Pipelines use the actual target sample count and render-pass compatibility, without assuming a color texture exists under MSAA. Production uses 1× sampling.

The completed SessionPane subtree is attached to the tab widget only after its QRhiWidget has enabled the RHI configuration. This lets Qt initialize RHI composition when a session is added to an already shown raster MainWindow, without global environment overrides. Desktop dimensions, pixel count, stride and clipboard payload sizes are bounded before copying/conversion. Sparse production updates avoid whole-desktop copy/upload work; this does not establish an independent display-clock scheduler or SDL performance parity.

Stop sets an atomic flag, requests FreeRDP's thread-safe abort under the context lifetime mutex, and wakes credential waiters. All ordinary FreeRDP connect/input/resize/event/disconnect/free operations remain on the worker. Context pointer publication/withdrawal is protected against abort racing with free. The worker disconnects (including channel-thread shutdown), clears channel pointers, frees GDI/context/instance, and exits. The GUI joins before deleting the worker or its view. GPU resources are released on the GUI thread in both `releaseResources()` and the derived destructor. Retired caches defer deletion past in-flight commands. Release preserves the CPU image and marks it for reupload; an explicit null frame clears the old desktop. Joining at tab teardown can briefly pause the GUI; an asynchronous shutdown UI is future hardening.

Tests cover frame ownership, queued generation isolation, explicit clearing, complete-resource failure/retry, retained-image recovery, MSAA/format changes, independent sessions, idle/burst behavior and repeated shutdown. Qt's opt-in `QT_RHI_LEAK_CHECK` is enabled during native renderer tests; unreleased-resource diagnostics fail them. A frame revision counts as presented only after window painting and a subsequent `frameSubmitted`; `grabFramebuffer()` rendering cannot set that evidence. Native tests require the revision evidence before pixel readback and fail on `QRhiWidget: No QRhi`. Offscreen/Null backends are not GPU-pixel oracles. Tests verify available DPR configurations and report unavailable live different-DPR transitions explicitly. These are runtime regression checks, not a formal race proof, ThreadSanitizer run, or SDL performance comparison.

### Isolated T36 branch

The independently built `build/macos/test-data/t36-candidate` starts at `ce1b429` and deliberately retains the full-QImage `takeFrame()` mailbox, original command ordering and 16 ms wait, GFX-disabled settings and decoder-free bootstrap. It selects the QRhi cache/readiness/presentation and current-worker/generation guards without the later damage, graphics-policy or trace interfaces described above. The only worker exception is `resizeRdpLegacyDesktop`: bounded negotiated dimensions, checked public planar reset before checked GDI resize, same-size no-op and ordinary failure teardown. ## Credentials and trust

The C++ RDP CredentialProvider asynchronously prompts for transient username/domain/password and clipboard permission; SSH uses its separate masked username/password or key/passphrase dialog. Production prompts are session-only, with no remember control. Quick Connect/different-credential actions never persist secrets, and prompt account edits do not change profiles. Config's dedicated C++ Set/Clear/Inheritance operations bypass QVariant/model commit, use masked empty editors and require explicit association review. A custom file master is optional; the public default provides only obfuscation.

`ConnectionCrypto` uses the native AES/GCM value envelope: PBKDF2-HMAC-SHA1, original single-byte master encoding, salt16/nonce16/tag16, salt as AAD. New files use ConfVersion 2.8 and 10000 iterations; supported 2.6–2.8 imported parameters remain. Full mode encrypts inner XML while keeping root attributes public and individual secrets encrypted. Unsupported crypto/parameters reject rather than falling back. Compatible PBKDF2 is weaker against password guessing than the retired Argon2id vault. See [format, backup and recovery rules](password-vault.md).

Private encrypted bindings check file/consumer/owner identities, actual ciphertext hash, source and committed protocol/endpoint/account. Exact v1 RDP remains compatible; v2 adds SSH Password with empty canonical Domain and rejects unknown/mismatched discriminators. Private-key mode never reuses saved Password as a passphrase and removes reuse authorization without deleting ciphertext. Native value AEAD alone does not authenticate public associations. Missing extensions require explicit native-import review; malformed present extensions reject. Removing every extension is indistinguishable from native input. Original resaves can drop bindings, app-only preferences and inactive archives. Default-key imports require review, not custom-master conversion; public-default-key bindings have no attacker-resistant authenticity.

`DocumentService` is a GUI-affine facade over the serialized worker. Lookup replies revalidate runtime document, generation/revision, profile binding, committed target and live page/panel/token before attach. Lock clears only the owning file's reusable master/cache and pending secret replies. It leaves opened metadata and active targets visible. Committed writes survive cancellation for owning-context reconciliation; password replies do not. Master change re-encrypts all known values, bindings/archive and optional inner XML in one replacement, without revoking old copies.

Retired vault readers/services are absent; historical backups still need their matching sidecars. No cross-file atomic transaction or backup revocation is claimed. The Rust CredentialProvider trait remains unavailable and there is no OS keychain integration. Move-only C++ Secret uses OPENSSL_cleanse; masked editors and transient Qt/FreeRDP/Rust authentication storage have best-effort release/clearing, not locked-memory or guaranteed zeroization.

Profile JSON includes nonsecret account/options/auth-method/key-path metadata, never credentials. Ordinary Core/snapshot/edit/session/role/log/capture channels are secret-free; only SSH's dedicated session-only authentication bridge carries password/passphrase input. Document masters/crypto keys remain C++-owned. FreeRDP logging is restricted to errors. Owned integration runners scan reports for generated secrets before displaying/saving them.

RDP certificates follow the profile's Server Authentication setting. "Accept unverified certificates for this session" (`server_auth=warn`, default) auto-accepts new, unverified, mismatched or changed certificates for that connection/session without a popup or saved trust. "Don't connect" (`required`) refuses certificates that are not CA-valid or previously trusted. "Always connect" bypasses verification without a banner. Existing FreeRDP known_hosts entries under the application-data `freerdp` directory remain honored; no new permanent trust is written. Server and gateway callbacks use the same policy, without changing TLS/NLA/CredSSP negotiation. Gateway passwords are asked per session and never saved; a gateway using the connection's credentials never receives a saved password automatically.

## Containment and external resources

- Native tools, SDKs, download and Python caches: `.dev/macos/`; native output: `build/macos/`, `dist/macos/`.
- Linux source-side Cargo/data/cache: `.dev/linux/`; architecture-separated output: `build/linux/<arch>/`, `dist/linux/<arch>/`. Linux SDKs are in project Docker image layers.
- `scripts/env.py` scopes PATH, Cargo/Rustup/build/cache variables, Qt/native prefixes and plugin/library paths to one child process. `HOME` and caller environment remain unchanged. Python bytecode writes are disabled for launched tests/tools so source directories are not caches.
- Existing Apple compiler/SDK/Python, Docker/OrbStack and optional editor are host prerequisites, not installed by bootstrap. The bootstrap does not edit shell files or register global package-manager integration.
- Docker VM storage, labeled images/containers/Compose networks and named Buildx cache volumes live outside the checkout. Only this project's names/labels are removed by Docker cleanup. Shared Ubuntu/BuildKit images and the OrbStack VM remain.
- Apt tools/libraries live inside the image. The base digest and SDK artifacts are pinned; apt repositories are not snapshot-pinned. `native-packages.txt` records the exact resolved image package versions.
- Devcontainer editor server files are directed to `.dev/linux/vscode-server`; editor extensions and host VS Code storage may still have their own caches outside this project. Editor setup was not validated.
- Without `--dev-root`, Qt chooses normal OS application-data outside the checkout. Cleanup never removes it. Development mode puts XML, FreeRDP config, independent SSH trust and terminal preferences under `.dev/<platform>/data`.

Cleanup defaults to dry-run, accepts only known generated directories, and rejects symlink escapes. Build/tool/package cleanup preserves profiles unless the user explicitly selects data cleanup. Source and unrelated Docker resources are outside its target set.
